    1 · Getting started
    
      
      
        
    1. Pick a problem. Choose a built-in example from Example, type your own in the
          Problem box (LP format, see §2), or click Upload… for an .lp / .mps file.
      2. 
        
    2. Choose the split variable (optional). Auto uses the first integer variable that is fractional
          in the LP optimum. After the first run, every fractional variable is listed.
      3. 
        
    3. Tick the cut families to compare (§5). You can select several at once.
      4. 
        
    4. Click Generate cuts. The results appear on the right: summary, cuts table, plot (2 or 3
          variables), bounds chart, solutions, and the simplex panel.
      5. 
        
    5. Solve completely. The Solve tab runs iterative cutting planes, branch and bound, or branch and
          cut on the same problem (§7).
      6. 
        
    6. Explore. Click legend entries to show or hide plot layers, step through the simplex iterations,
          switch on Fractions for exact values, or open the Analysis tab.
      7.

    2 · Writing a problem
    
      
    Problems use the standard CPLEX LP format; MPS is accepted too (switch the format toggle,
        or upload a .mps file).
    
      
    Maximize                      (or Minimize)
 obj: 5 x + 4 y
Subject To
 labor:    6 x + 4 y <= 24.5    (<=, >= and = are allowed)
 material: x + 2 y <= 6.5
Bounds                        (optional; default 0 <= var < +inf)
 x <= 3
General                       (integer variables)
 x y
End
    
      
    Rules
    
      
      
        
    • Every variable must have a lower bound ≥ 0. The cut generators work in standard form, x ≥ 0.
      • 
        
    • At least one variable must be integer: list it under General, or under Binary for
          0/1 variables.
      • 
        
    • GFC also needs every variable to be integer (§5.1). The other cuts work for mixed-integer problems.
      • 
        
    • The feasible-region plot is drawn only for problems with 2 or 3 variables. Everything else works for any size,
          and the simplex iterations are shown for up to 40 rows.
      • 
      
    
    
    

    
    
      
    3 · What happens when you click Generate
    
      
      
        
    1. Solve the MIP with HiGHS, to know the integer optimum z_IP for the gap calculation.
      2. 
        
    2. Solve the LP relaxation (integrality dropped). Its optimum x̄ gives the LP bound
          z_LP. If x̄ is already integral, no cut is needed.
      3. 
        
    3. Standard form: max c'x  s.t.  Ax ≤ b, x ≥ 0. ≥ rows are negated, = rows become two rows,
          variable bounds become rows, and a Min objective is negated. Each row keeps a label (c1,
          x1 ≤ 1, …).
      4. 
        
    4. Normal form: one slack per row, Ax + s = b. Slack sᵢ belongs to row
          i.
      5. 
        
    5. Optimal tableau from the solver's basis: B⁻¹A, B⁻¹b and the reduced costs.
          Tableau cuts (GFC, SIC, GMI) read one of its rows; VPCs use one tableau for each side of the split.
      6. 
        
    6. Generate each selected cut α'x ≥ β in the original variables.
      7. 
        
    7. Evaluate: add the cut to the relaxation and solve again to get z_cut. For 2-D and 3-D
          problems, also check the cut against every feasible integer point.
      8. 
      
    
      
    gap closed (%) = 100 · (z_cut − z_LP) / (z_IP − z_LP)
    
    
    

    
    
      
    4 · The simplex panel
    
      
    It shows the LP relaxation in standard form, where every problem is a maximization. For a Min problem,
        the z in the tableau is −(original objective).
    
      
    Iterations tab
    
      
    A textbook two-phase simplex, one tableau per step.
    
      
      
        
    • Phase I appears only if some right-hand side is negative. Those rows are multiplied by −1 and get an
          artificial variable aᵢ; Phase I maximizes −Σ aᵢ to reach a feasible basis.
      • 
        
    • Phase II then maximizes the real objective.
      • 
        
    • Bland's rule: the entering variable is the first column with a negative reduced cost, and ties in
          the ratio test go to the smallest basic index. This rule guarantees the simplex never cycles.
      • 
        
    • Highlighting: shaded column = entering variable; shaded row = leaving variable; boxed cell =
          pivot; last column = ratio test (rhs ÷ entry for positive entries).
      • 
      
    
      
    Tableau rows:  x_B + B⁻¹N x_N = B⁻¹b
Objective row: z + d'x = z̄,   with reduced costs  d = c_B'B⁻¹A − c   (optimal when d ≥ 0)
    
      
    Analysis tab
    
      
    
        
    CheckMeaning
    
        
    B⁻¹b ≥ 0the basis is primal feasible
    
        
    reduced costs ≥ 0no improving column, so the basis is optimal
    
        
    basic columns = identitythe tableau is internally consistent
    
        
    values, objective = solver'sthe tableau reproduces HiGHS's solution
    
        
    c_B'B⁻¹ = shadow pricesthe simplex multipliers (duals) agree with the solver's
    
        
    textbook simplex agreesan independent algorithm reaches the same optimum
    
      
    
      
      
        
    • Reduced cost of a non-basic variable: how much z drops per unit you force that variable up.
          Zero means there may be alternative optima.
      • 
        
    • Shadow price of a row: how much z changes per unit increase of that row's right-hand side.
          A row is binding when its slack is 0.
      • 
        
    • Degenerate vertex: a basic variable equal to 0. A pivot at such a vertex can leave z unchanged.
      • 
      
    
    
    

    
    
      
    5 · Cut families
    
      
    Every cut is a linear inequality α'x ≥ β that removes the LP optimum x̄ but keeps every
        feasible integer point. All five start from the same split variable x_k, an integer variable with a
        fractional value x̄_k.
    
      
    Optimal-tableau row of x_k:   x_k + Σ_{j non-basic} ā_j x_j = b̄,     f0 = b̄ − ⌊b̄⌋ ∈ (0, 1)
Split disjunction:            x_k ≤ ⌊x̄_k⌋   or   x_k ≥ ⌈x̄_k⌉
    

      
    
        
    5.1 Gomory fractional cut (GFC) — Gomory 1958
    
        
    
          
    Idea
    Solve the LP relaxation and pick the tableau row of a fractional basic variable. For integer
            values, Σ frac(ā_j)x_j and f0 are congruent modulo 1, and Σ frac(ā_j)x_j is non-negative, so it must be
            at least f0.
    
          
    Cut
    Σ_{j non-basic} frac(ā_j) · x_j  ≥  f0          frac(a) = a − ⌊a⌋
    
          
    Valid for
    Pure integer problems only. Every non-basic variable, slacks included, must be
            integer. Each row is therefore first scaled to integer coefficients, so that its slack is integer at integer
            points. For example, −2x₁ − 2x₂ ≤ −0.5 becomes −4x₁ − 4x₂ ≤ −1. Problems with
            continuous variables are refused; use GMI for them.
    
          
    In the lab
    The cuts table shows the derivation: the source row, f0, the fractional parts, the cut in
            the non-basic variables, and the slack substitution.
    
          
    Julia
    gomory_fractional_cut(std_model, k, integer_vars) → (α, β, rescaled, derivation),
            or generate_cut(relaxed, k, integer_vars, :gfc)
    
        
    
        
    Worked example (toy problem): the row is x1 + x2 − ¼ s1 = ¼, so the fractional parts
          are 0 and ¾, and the cut is ¾ s1 ≥ ¼. With s1 = −1 + 4x1 + 4x2,
          this becomes x1 + x2 ≥ ⅓.
    
      
    

      
    
        
    5.2 Standard intersection cut (SIC) — Balas 1971
    
        
    
          
    Idea
    Take the LP cone at x̄, with one ray per non-basic variable. Walk along each ray
            until x_k reaches ⌊b̄⌋ or ⌈b̄⌉, and pass the cut through those
            intersection points. Nothing integer lies strictly between the two split hyperplanes.
    
          
    Cut
    λ_j = f0 / ā_j  if ā_j > 0,   (1 − f0) / (−ā_j)  if ā_j < 0,   ∞  if ā_j = 0
Σ_j x_j / λ_j  ≥  1
    
          
    Valid for
    Any mixed-integer problem; only x_k needs to be integer.
    
          
    Julia
    sic_cut(std_model, k) → (α, β, λ, derivation), or
            generate_cut(relaxed, k, integer_vars, :sic)
    
        
    
      
    

      
    
        
    5.3 Gomory mixed-integer cut (GMI)
    
        
    
          
    Idea
    The SIC, with the coefficients of integer non-basic variables strengthened. Shifting an
            integer variable by a whole number keeps the point on the correct side of the split.
    
          
    Cut
    Σ_{j integer}    min( f_j/f0 , (1 − f_j)/(1 − f0) ) x_j
+ Σ_{j continuous} max( ā_j/f0 , −ā_j/(1 − f0) )     x_j   ≥  1          f_j = frac(ā_j)
    
          
    Valid for
    Any mixed-integer problem. Slacks are treated as continuous. GMI is never weaker than
            SIC, and the two coincide when every non-basic variable is continuous.
    
          
    Julia
    gmi_cut(std_model, k, integer_vars) → (α, β, derivation), or
            generate_cut(relaxed, k, integer_vars, :gmi)
    
        
    
      
    

      
    
        
    5.4 V-polyhedral cut (VPC) — Balas & Kazachkov
    
        
    
          
    Idea
    Solve each side of the split as its own LP. Each side t has its own optimal vertex
            p_t and cone rays R_t. Any inequality valid for all these points and rays is valid
            for the union of the two sides, and therefore for every integer point. This describes each side better than
            the single cone at x̄ used by SIC and GMI.
    
          
    Cut
    Solve the point-ray LP (PRLP):
    min α'x̄   s.t.   α'p_t ≥ β   (each side's vertex),    α'r ≥ 0   (each ray r)
    
            Normalization (PRLP normalization menu): β = 1 (original), ‖α‖₁ ≤ 1 (always bounded),
            or Auto (β = 1, falling back to ℓ1 when that LP has no optimum).
    
          
    Special case
    If one side is infeasible, the other side's split row is itself the cut.
    
          
    Julia
    create_disjunctive_subproblems → process_subproblem →
            solve_prlp, or generate_cut(relaxed, k, integer_vars, :vpc)
    
        
    
      
    

      
    
        
    5.5 VPC + monoidal strengthening — Balas & Jeroslow 1980
    
        
    
          
    Idea
    Write the VPC on each side as a combination of that side's rows (Farkas multipliers
            u_t). Replacing the split e_k by e_k + μ, with μ integer
            on the integer variables, is still a valid split, so each integer coefficient can choose the best shift.
    
          
    Cut
    α̃_j = min_{μ ∈ ℤ} max( α¹_j − u0¹ μ ,  α²_j + u0² μ )   for integer j;   α̃_j = α_j otherwise
    
            β stays the same and α̃ ≤ α, so the cut is never weaker than the VPC.
    
          
    Julia
    prepare_monoidal_data → monoidal_strengthening, or
            generate_cut(relaxed, k, integer_vars, :vpc_mono)
    
        
    
      
    

      
    
        
    5.6 Comparing them
    
        
    
          
    CutRelaxation usedInteger strengtheningProblems
    
          
    GFCone tableau row at x̄fractional roundingpure integer
    
          
    SICLP cone at x̄nonemixed integer
    
          
    GMILP cone at x̄integer coefficientsmixed integer
    
          
    VPCeach side's own vertex and conenonemixed integer
    
          
    VPC + monoidaleach side's own vertex and coneinteger coefficientsmixed integer
    
        
    
        
    Always true: GMI is at least as strong as SIC, and VPC + monoidal is at least as strong as VPC. The other
          pairs depend on the instance, which is what the lab is for. GFC is often the weakest, but because it uses
          integer slacks it can beat GMI on some coefficients.
    
      
    
    
    

    
    
      
    6 · Reading the results
    
      
      
        
    • Summary — objective sense, LP bound, MIP optimum, split variable and the number of fractional
          variables.
      • 
        
    • Cuts table — each cut's inequality and derivation, the new LP bound after adding it, the percentage
          of the gap closed, and the validity check: whether the cut keeps all feasible integer points (2-D and
          3-D problems). A red INVALID badge would mean a bug. Does not cut off the LP optimum means the
          cut is valid but useless here.
      • 
        
    • Feasible region — the LP relaxation (blue), the integer hull (dotted green), feasible integer points
          (green dots), the LP optimum (red star), the MIP optimum (green diamond), and for each cut its line or plane, the
          region it leaves, and the new LP optimum (×). The 3-D view can be dragged to rotate.
      • 
        
    • Bounds — LP bound, each cut's bound, and the MIP optimum, side by side.
      • 
        
    • Solutions — variable values at the LP optimum, the MIP optimum, and after each cut.
      • 
      
    
    
    

    
    
      
    7 · Solve tab: iterative methods
    
      
    The Lab adds one cut at a time. The Solve tab runs complete algorithms on the problem in the Lab
        editor until the MIP is solved, or until a limit is reached. Pick an algorithm, set its options, and press
        Solve.
    

      
    
        
    7.1 Cutting planes · one cut family
    
        
    repeat
  solve the LP (relaxation + every cut so far)
  if the LP solution is integer → it is optimal for the MIP, stop
  for each chosen fractional variable: generate a cut of the selected family
  add every cut that cuts off the LP solution
until no cut separates, the bound stalls for 5 rounds, or the round limit
    
        
      
          
    • Cut on: first or most fractional variable (one cut per round), or every
            fractional variable (one cut per variable per round: more cuts, usually fewer rounds).
      • 
          
    • GFC on a pure-integer problem is Gomory's classical cutting-plane algorithm. With the right
            precautions it is guaranteed to finish in finitely many rounds. On the small built-in examples it reaches the
            optimum in a few rounds, helped by the integer rounding below.
      • 
          
    • Pure-integer rounding: when every variable is integer, each new cut is scaled to integer
            coefficients and its right-hand side is rounded up (Chvátal–Gomory). This is valid because
            α'x is an integer at integer points. It makes cuts slightly stronger and keeps the data
            integral, so GFC stays exact in later rounds.
      • 
          
    • Tailing off: later rounds often improve the bound less and less, as the convergence chart
            shows. This is why solvers combine cuts with branching.
      • 
        
    
      
    

      
    
        
    7.2 Cutting planes · several families together
    
        
    The same loop, but every round adds the cuts of all ticked families, for example GMI + VPC. The rounds
          table lists how many cuts of each family were added, and which were skipped and why (e.g. GFC on a
          mixed-integer problem, or a cut that does not separate).
    
      
    

      
    
        
    7.3 Branch and bound
    
        
    start with the root node (the LP relaxation)
while there are open nodes:
  pick a node (best bound / depth first / breadth first) and solve its LP
  prune it if the LP is infeasible                      (red)
  prune it if its bound cannot beat the incumbent       (orange)
  if its solution is integer → new incumbent candidate  (green)
  otherwise pick a fractional x_k (most / first fractional) and create
     two children:  x_k ≤ ⌊x̄_k⌋   and   x_k ≥ ⌈x̄_k⌉       (blue = branched)
    
        
      
          
    • Best bound explores the node with the best LP bound first. It usually solves the fewest nodes.
            Depth first finds integer solutions sooner and uses little memory. Breadth first goes level by
            level.
      • 
          
    • Incumbent = best integer solution found so far. Best bound = the best LP bound among open
            nodes. When the two meet, the incumbent is optimal; the convergence chart shows both curves.
      • 
          
    • The tree shows every node with its branching constraint on the edge. Hover or click a node for its
            bound and LP solution; the star is the optimal node. The table lists the nodes in the order they were
            solved.
      • 
          
    • Replay the search with ▶ Play or the slider: nodes appear in the order they were solved, the node just
            solved is ringed, nodes created but not yet solved are hollow, and the label gives the incumbent and best bound
            at that step. Each solved node shows its LP bound (and ✂ the cuts added there).
      • 
          
    • Compare B&B and B&C runs both on the same problem and settings and shows the two trees side by
            side, with nodes, depth, root bound, cuts and time; the better value of each is in bold.
      • 
        
    
      
    

      
    
        
    7.4 Branch and cut
    
        
      
          
    • Cut rounds at the root: before branching, run cutting-plane rounds with the ticked families. Root
            cuts are valid for the whole problem, so they are added to every node. The summary shows how much of the
            gap they closed at the root.
      • 
          
    • Cut rounds at every node: optional. Cuts found at a node use that node's branching bounds, so they are
            valid only in its subtree (local cuts) and are passed to its children only.
      • 
          
    • Cuts tighten the bounds, so more nodes are pruned. On the built-in examples, branch and cut often proves
            optimality at the root, with a tree of one node.
      • 
        
    
      
    

      
    
        
    7.5 Reading the Solve results
    
        
      
          
    • Status: Optimal — proven; no cut separates; bound stalled; round / node
            limit reached.
      • 
          
    • Convergence: the LP bound per round, or the best bound and incumbent per node, against the MIP
            optimum from HiGHS (dotted).
      • 
          
    • Feasible region (2 or 3 variables): for cutting planes, a slider replays the rounds. It shows the
            region left after each round, that round's cuts in bold, earlier ones faded, and the current LP optimum. For
            branch and bound it shows the root cuts and every node's LP solution, labelled by node number.
      •

    One cut in a few lines
    
      
    using CuttingPlane, JuMP

model   = read_model("model.lp")           # or build it with JuMP
relaxed = relax_model(model);  optimize_model!(relaxed)
ints    = integer_variable_indices(model)
k       = first(fractional_integer_variables(relaxed, ints))

cut = generate_cut(relaxed, k, ints, :gmi)  # :gfc, :sic, :gmi, :vpc, :vpc_mono
println(cut.note)                           # derivation / remarks
tightened = add_cut(relaxed, cut.α, cut.β)
optimize_model!(tightened)
objective_value(tightened)
    
      
    Step by step (what generate_cut does)
    
      
    std     = create_standard_form_model(relaxed)    # max c'x, Ax ≤ b, x ≥ 0
normal  = create_normal_form_model(std)          # Ax + s = b
optimize_model!(normal)
opt     = generate_optimal_simplex_tableau(normal)   # tableau, basis, non-basic, …
verify_optimal_tableau(normal)                   # the six checks of the Analysis tab
run     = tableau_simplex(std)                   # textbook two-phase simplex, every step

# VPC by hand
sides, D0 = create_disjunctive_subproblems(std, k, ints)
foreach(optimize_model!, sides)
res   = [process_subproblem(s) for s in sides]       # vertex + rays of each side
ω, _  = get_variable_values(relaxed)
_, α, β = solve_prlp(ω, [r.point for r in res], [r.rays for r in res]; normalization = :auto)

    11 · Glossary
    
      
    
        
    LP relaxation
    The problem with integrality dropped; its optimum is a bound on the MIP.
    
        
    Cut
    An inequality satisfied by every feasible integer point but violated by the current LP optimum.
    
        
    Split disjunction
    x_k ≤ ⌊x̄_k⌋ or x_k ≥ ⌈x̄_k⌉: every integer point satisfies one of the two sides.
    
        
    Basis
    The m columns that the current vertex is solved for; the other variables are 0.
    
        
    Reduced cost
    The rate at which z changes when a non-basic variable increases.
    
        
    Shadow price
    The rate at which z changes when a row's right-hand side increases.
    
        
    Degenerate
    A vertex where some basic variable is 0, so several bases describe the same point.
    
        
    Integer hull
    The convex hull of the feasible integer points; the ideal relaxation.
    
        
    Gap closed
    The share of the gap between the LP bound and the MIP optimum that a cut removes.
